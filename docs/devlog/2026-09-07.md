## 遇到的问题 / 怎么解决的（都是交叉编译的典型坑）
- **问题：编错架构** —— 默认 `/usr/bin/c++` 是 x86，需换 **aarch64 交叉编译器**（用 SDK buildroot 的 `aarch64-buildroot-linux-gnu-g++`）。
- **问题：`ld: 找不到 -lrknnrt`** —— rknpu2 的库不在 `librknn_api/lib`，而在 **`librknn_api/aarch64/`** 子目录（Linux 下分 armhf/aarch64）。
- **问题：`rknn run` 报 `failed to submit! OutputOperator ... size_with_stride`** —— 对量化模型设 `want_float=0`(取 int8) 会触发 NPU 跑 OutputOperator，此模型/版本不支持。
  解决：**统一 `want_float=1`(取 float) + fp 解码**，与板上 python(rknnlite) 验证路径一致 → 成功。
  备注：后续要 int8 高性能可改用 `rknn_create_memory(size_with_stride)` 零拷贝。
- **注意：runtime 版本匹配** —— 头/库用 `rknpu2-1.5.0`（与板上 `librknnrt 1.5.0` 一致），不能用 SDK 老版本。
