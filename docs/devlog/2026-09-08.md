## 遇到的问题 / 怎么解决的
- **问题：video 模式看不到 ROI 黄线** —— 该模式原本不生成预览（只有 cam/pipe 有）。解决：首帧调 `draw_roi_and_save` 存图。
- **问题：WiFi `ifconfig wlan0 up` 报 RF-kill** —— 板 WiFi 被软件射频开关锁。解决：`rfkill unblock all` 后 `up` 成功。
- **问题：`wpa_passphrase` 写坏配置** —— 密码 `123456` 只有 6 位（WPA 要求 ≥8 位），错误提示被 `>>` 追加进 conf 第 4 行导致解析失败。
  解决：`printf` 重建头 + `wpa_passphrase "真实SSID" "≥8位密码"`，SSID 用 `iw dev wlan0 scan` 查真实名称。
- **问题：板 `ping 192.168.1.163` 100% 丢包** —— 一度怀疑 ChinaNet 光猫 AP 隔离。
  排查：Windows 反向 ping 板**通** → 判定非 AP 隔离，只是 Windows 防火墙默认挡入站 ICMP；**ping 不通不代表 TCP 不通**。
  权威验证：Qt 端监听 + 板上 python 发一条 TCP 测试消息 → 收到 → 链路 OK。
- **问题：首次 Qt 工程路径拼错**（`yk3688` vs `rk3568`）—— 打开正确 `host/qt_gui/intruder_gui.pro` + 选唯一 MinGW 32bit kit 解决。

## 晚间补记：告警图片 + 现场准实时预览链路（Qt 画面最终打通）
> 在上午跨机事件流基础上，为演示加"画面"。整条：板端 ALARM 缩略图(320×180 RGB→base64) + 周期性现场预览帧 → Qt 右侧持续显示。

### 踩坑记录（网络/解码，都有价值）
- **弱 WiFi 导致 TCP 积压**：ChinaNet-503 信号 -93dBm，预览 320×180@0.5s(460KB/s) 远超弱网吞吐 → 板端数据积压 → Qt 迟迟收不到完整帧、**关闭程序要 10s 才显示断开**。
  解决：预览先压到 160×90@1s(58KB/s)；换**手机热点**(华为 P60，快网) 后事件与图片秒达。
- **多连接共用一个半包缓冲 → 行交错解析失败**：反复重连 pipe(断开慢) 在 Qt 累积多个 socket，都往同一个 `buf_` 写 → JSON 行被拆乱 → 图片 `thumb_w/h` 解析为 0。
  解决：**每连接独立缓冲**(QHash<QTcpSocket*,QString>)。
- **`jsonInt` 用 `mid+toInt` 对 `160,"thumb_h":…` 返回 0**（原因不明）→ 改**逐字符解析数字**修复。
- **Qt 重编报 Permission denied**：旧 exe 进程占用 → 先 `Get-Process intruder_gui | Stop-Process -Force` 再构建。
- 收尾：预览调回 **320×180@~3fps**（手机热点快网流畅清晰，弱网可退回 1s/160×90）。
