## 遇到的问题 / 怎么解决的
1. **问题：OpenCV/GStreamer 打不开 MIPI OV13850，`unable to start pipeline`、读不出帧。**
   - 初判以为"例程配的是 iMX415"——❌ **不是**。用 `v4l2-ctl --list-devices / media-ctl` 确认：OV13850 已被系统绑定，节点就是 rkisp mainpath `/dev/video0`。
   - 继续深挖：`v4l2-ctl` 裸抓 mainpath 也卡死；`dmesg` 显示 sensor/CSI/ISP 链路有帧(`frame:5`)，
     但卡在 `rkisp: waiting on params stream on event timeout`。
   - **结论**：MIPI 出图 = sensor 驱动 + rkisp + **rkaiq/3A 用户态 + 对应 sensor 的 tuning** 三件套。
     `rkaiq_3A_server` 在跑但 tuning 与 OV13850 不匹配 → mainpath 永远等不到帧。**属板级固件范畴，demo 改不了**。
   - **规避**：算法验证阶段不依赖摄像头，改用图片/视频文件（后续 D2 用图片在板上验证推理链）。
   - 经验价值：能讲清"为什么 MIPI 摄像头不是插上就能用 / ISP 为什么需要 3A"。
2. **问题：板端装错 rknn 库（`rknn-toolkit2` 只能在 x86 训练机跑，板端 init runtime 报错）。**
   - 解决：板端装 `rknn-toolkit-lite2` / `rknnlite`，不指定 target 默认跑本机 runtime。
3. **问题：打不开 NPU 设备 `/dev/rknpu`（权限不足）。**
   - 解决：root 运行或把用户加入 `npu` 组。
