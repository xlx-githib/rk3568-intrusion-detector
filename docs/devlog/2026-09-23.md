## 遇到的问题 / 怎么解决的
- **问题：画面 4s 才跟上** → 误以为要调编码参数（gop/qp），实际是播放器默认缓冲 5s。
  **解决**：先用"延迟拆解表"逐段估算，锁定播放器；`-probesize 32 -analyzeduration 0 -fflags nobuffer` 解决。
  顺带把 `gop` 从默认（-1=按帧率，约 1s 一个 I 帧）改成 15（0.5s），随机接入更跟手。
- **问题：怎么"既推流又检测"** → 外部 `gst-launch` 会和程序**抢 `/dev/video0`**。
  **解决**：改成进程内 `appsrc`，采集层一次拿帧、两份表示（RGB 给 NPU、NV12 给编码器）。
- **问题：推流会不会拖慢采集/推理** → `appsrc` 设 `block=false` + `max_bytes≈3 帧`，
  满了 `push_buffer` 直接失败 → 我们自己丢帧并计数，**采集线程永不被阻塞**。
- **问题：老构建不能被 gst 依赖污染** → 编译期开关 + 头文件类型擦除 + 空实现三件套。

## 踩坑（本日新增）

### 1. 交叉编译链接 gst：把 staging 加进 `-L` 会让链接器去找 `/lib64/libc.so.6`
- 现象：`ld: 找不到 /lib64/libc.so.6 / libc_nonshared.a / ld-linux-aarch64.so.1`
- 原因：`staging/usr/lib` 里有 glibc 的**链接脚本** `libc.so`，内容 `GROUP ( /lib64/libc.so.6 ... )`
  是**板端绝对路径**；gcc 默认会传 `-lc`，`-L` 一旦命中了它，ld 就去宿主根目录找了
- 修复：不把 staging 加进 `-L`，改成**绝对路径点名链接** `${GSTREAMER_ROOT}/lib/lib*.so` +
  `-Wl,-rpath-link,${GSTREAMER_ROOT}/lib`（rpath-link 只匹配 `libc.so.6` 这种带版本的真实文件名，不会命中脚本）

### 2. 头文件自足性：`size_t` 要显式 `#include <cstddef>`
- `<cstdint>` 只保证 `uint8_t` 这类定长类型，**不含 `size_t`**；Windows IntelliSense 宽容，板端 GCC 直接报错

### 3. `quit` 不退出（要 Ctrl+C）——根因是上报 `connect()` 阻塞
- 现象：PC 上位机关了 → 上报断开 → 控制台敲 `quit` 打印“退出中”，但卡住，要 Ctrl+C
- 原因链：上报断开 → 输出线程每个**预览帧**（333ms 一次）都调 `Reporter::connect()` 重连 →
  旧版是**阻塞 connect**，PC 未监听时内核 SYN 重试**几十秒** → 输出线程卡死 → `join()` 永远等不到 → 进程不退出
- 修复：`connect` 改**非阻塞 + poll 自控超时**（poll 可写 ≠ 连上，必须查 `SO_ERROR`）、
  重连加 2s 冷却、**退出时跳过预览上报**（`if (quit) continue`，好让 evQ 快速排空）
- 教训：**任何在网络路径上的阻塞调用，都会把“优雅退出”变成不可能**；能用超时就用超时

## 迭代3：板端 Qt 界面（同日启动，Step1 + Step2 完成）

### 环境探测（关键结论）
- 板子固件是 **Weston + Wayland** 架构：`/usr/bin/weston -w`（合成器，持有 DRM master）
  + `/opt/ui/systemui`（正点原子出厂 UI，Wayland 客户端）+ `weston-desktop-shell`
- 板上 Qt 5.15.2 模块齐全；平台插件只有 `linuxfb / wayland-egl / wayland-generic / offscreen / vnc`，
  **没有 eglfs**
- 屏幕：fb `1080x1920@32bpp`，但 **Wayland 逻辑尺寸 `720x1280`（竖屏）**；`card0/card1` + 触摸输入 event0~8
- SDK：`staging` 里有 **Qt5 头文件 + .so**，但**没有 host qmake/moc**
  → 不用 qmake，直接手写 `aarch64-...-g++` 命令，且**不用 `Q_OBJECT`**（信号槽全用 lambda），完全绕开 moc

### 显示路线：两条死路 + 正解（重要）
1. `QT_QPA_PLATFORM=linuxfb` → `Failed to mmap framebuffer (Invalid argument)` +
   `linuxfb: Failed to initialize screen` + `no screens available` → abort。
   原因：`/dev/fb0` 是 **DRM 模拟的 fbdev 节点**，Qt 按 `virtual_size × bpp/8` 算的 mmap 长度
   和驱动 `smem_len` 对不上
2. `QT_QPA_FB_DRM=1` → 屏幕**亮一下就恢复正常界面**：Qt 确实画上去了，但 weston 是 DRM master，
   立刻把显示抢回去（“瞬间亮一下”就是铁证）
3. ✅ 正解：**当 Wayland 客户端**
   ```bash
   export XDG_RUNTIME_DIR=/run      # 别用 /var/run（符号链接，Qt 会抱怨）
   QT_QPA_PLATFORM=wayland ./rkqttest
   ```
   —— 这也解释了为什么插件里有 `wayland-egl` 却没有 `eglfs`：固件本来就按 Wayland 配的

### Step 2 视频接入（完成）
```
主程序 tcpserversink:5000 ─127.0.0.1→ 板端 Qt
  tcpclientsrc ! tsdemux ! h264parse ! mppvideodec(硬解)
  ! videoscale ! videoconvert ! video/x-raw,format=RGB,width=640,height=360
  ! appsink(max-buffers=2, drop=true)
  → 拉帧线程只存“最新一帧” → UI QTimer 取 → QImage 画到视频区
```
- 实测：**解码收帧 1463 / UI 显示 1184 / 顶掉 279（≈19%）**，UI 31.3 fps
  → 丢帧策略生效，**延迟不会堆积**（这是设计目标，不是缺陷）
- 优化：取帧轮询 33ms→10ms，并**只在拿到新帧时重绘**（顶掉率下降、省 CPU）
- 坑：`tcpclientsrc` 是主动连接，**推流端没起时整个管道直接进 error**（报
  `PLAYING 状态切换失败`）→ 必须加 bus 监听 + 拆掉重建的**自动重连**（每秒重试）。
  否则主程序一停，Qt 端就再也连不上了
- 结果：**板端全链路（V4L2 采集 + NPU 检测 + 硬编码 + 硬解码 + Qt 显示）同时跑通**
  （此时主程序检测帧率从 16.7 降到 14.0 fps —— 多了一份硬解 + Qt 渲染的开销）
