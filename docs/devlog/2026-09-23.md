## 遇到的问题 / 怎么解决的
- **问题：画面 4s 才跟上** → 误以为要调编码参数（gop/qp），实际是播放器默认缓冲 5s。
  **解决**：先用"延迟拆解表"逐段估算，锁定播放器；`-probesize 32 -analyzeduration 0 -fflags nobuffer` 解决。
  顺带把 `gop` 从默认（-1=按帧率，约 1s 一个 I 帧）改成 15（0.5s），随机接入更跟手。
- **问题：怎么"既推流又检测"** → 外部 `gst-launch` 会和程序**抢 `/dev/video0`**。
  **解决**：改成进程内 `appsrc`，采集层一次拿帧、两份表示（RGB 给 NPU、NV12 给编码器）。
- **问题：推流会不会拖慢采集/推理** → `appsrc` 设 `block=false` + `max_bytes≈3 帧`，
  满了 `push_buffer` 直接失败 → 我们自己丢帧并计数，**采集线程永不被阻塞**。
- **问题：老构建不能被 gst 依赖污染** → 编译期开关 + 头文件类型擦除 + 空实现三件套。

## 踩坑（本日新增）

### 1. 交叉编译链接 gst：把 staging 加进 `-L` 会让链接器去找 `/lib64/libc.so.6`
- 现象：`ld: 找不到 /lib64/libc.so.6 / libc_nonshared.a / ld-linux-aarch64.so.1`
- 原因：`staging/usr/lib` 里有 glibc 的**链接脚本** `libc.so`，内容 `GROUP ( /lib64/libc.so.6 ... )`
  是**板端绝对路径**；gcc 默认会传 `-lc`，`-L` 一旦命中了它，ld 就去宿主根目录找了
- 修复：不把 staging 加进 `-L`，改成**绝对路径点名链接** `${GSTREAMER_ROOT}/lib/lib*.so` +
  `-Wl,-rpath-link,${GSTREAMER_ROOT}/lib`（rpath-link 只匹配 `libc.so.6` 这种带版本的真实文件名，不会命中脚本）

### 2. 头文件自足性：`size_t` 要显式 `#include <cstddef>`
- `<cstdint>` 只保证 `uint8_t` 这类定长类型，**不含 `size_t`**；Windows IntelliSense 宽容，板端 GCC 直接报错

### 3. `quit` 不退出（要 Ctrl+C）——根因是上报 `connect()` 阻塞
- 现象：PC 上位机关了 → 上报断开 → 控制台敲 `quit` 打印“退出中”，但卡住，要 Ctrl+C
- 原因链：上报断开 → 输出线程每个**预览帧**（333ms 一次）都调 `Reporter::connect()` 重连 →
  旧版是**阻塞 connect**，PC 未监听时内核 SYN 重试**几十秒** → 输出线程卡死 → `join()` 永远等不到 → 进程不退出
- 修复：`connect` 改**非阻塞 + poll 自控超时**（poll 可写 ≠ 连上，必须查 `SO_ERROR`）、
  重连加 2s 冷却、**退出时跳过预览上报**（`if (quit) continue`，好让 evQ 快速排空）
- 教训：**任何在网络路径上的阻塞调用，都会把“优雅退出”变成不可能**；能用超时就用超时
