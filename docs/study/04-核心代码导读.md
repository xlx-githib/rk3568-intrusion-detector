# 核心代码导读与项目串讲（study/04）

> 本文是对 M1 闭环核心代码的梳理总结：先讲清整体思路，再逐个文件导读，
> 说明每段代码的作用与设计取舍，方便读者快速理解本项目是怎么实现的。

---

## 1. 一句话串起整个项目

> 把官方 RKNN demo 封装成 `RknnEngine`（检测内核），写 `RoiMonitor`（警戒区状态机），
> 在板上用视频帧跑通「检测 → 进入/告警/离开 → 截图」闭环。M2 将其改成摄像头 + 多线程流水线。

```
[帧] → RknnEngine.infer() → DetObject[](person/car, 已白名单)
                        ↓
          RoiMonitor.feed(dets, now) → Event[](INTRUDE/ALARM/LEAVE/RESOLVE)
                        ↓
              ALARM → 画框截图存 shots/
```

---

## 2. 三文件导读（M1 闭环）

### 2.1 `src/infer/rknn_engine.*` —— 检测内核（封装官方 demo）
- 设计：把模型生命周期 + 单帧推理收进类，对外只暴露 `init / infer / release`。
- `load_model_and_query()`：读 `.rknn` → `rknn_init` → `rknn_query`(IO 个数、输入输出属性)。
- `infer()`：BGR→RGB → letterbox 成 640×640 → `rknn_inputs_set/run/outputs_get` →
  解码 + NMS → 坐标回映射 → 白名单过滤 → 填 `DetObject`(含底部中心 `bx/by`)。
- 要点：`want_float=1`(fp 解码) 与板上 python 路径一致，规避 NPU OutputOperator 的 size_with_stride 问题；
  白名单目前由 `watch_cls_` 参数控制（笔者认为业务过滤放业务层更通用，重构时可挪）。
- 提速方向：letterbox 换 RGA 硬件缩放；int8 高性能可 `rknn_create_memory(size_with_stride)`。

### 2.2 `src/business/roi_monitor.*` —— 警戒区状态机（业务核心）
- 状态：`IDLE → INSIDE(计时) → ALARMED`；事件 `INTRUDE/ALARM/LEAVE/RESOLVE`。
- **帧级判定**：白名单目标"框底部中心 `bx,by`"落在 ROI 内即视为进入——
  框底部≈人的脚，头伸进来不算入侵，避免路过误报。
- 停留计时用 `now_us`；告警只触发一次（防重复刷屏）。
- 简化约定（第一版）：不做多目标跟踪，多人同时进出会近似合并；可升级为逐类独立状态机或中心点 IoU 关联。

### 2.3 `src/main.cpp` —— 调度入口
- 模式1(单图) / 模式2(video 帧序列：读 meta + `f_%04d.rgb` → 逐帧 infer → feed → 告警截图)。
- 离线帧序列用「帧号×帧率」模拟时间喂状态机；将来接摄像头换成 `Frame.pts_us` 真实时间戳。
- M2 会把它从"单线程串行"改造成四线程流水线；`RknnEngine`/`RoiMonitor` 即 Infer/Business 线程内核。

---

## 3. M1 达成要点（板上实测）
- 视频帧序列 444 帧 @640×289 / 10fps：`INTRUDE(帧0) → ALARM(帧30, stay=3000ms) + 告警截图`。
- 状态机行为符合设计；LEAVE/RESOLVE 需"单人进出"素材复验。

## 4. M2 预告（真摄像头 + 多线程 + socket 上报）
- 采集：V4L2 应用层从 OV13850 mainpath 取 NV12 → 转 RGB 喂引擎（风险点：rkisp 出帧需 3A 使能，板上先探路）；
- 工程：Capture/Infer/Business/Output 四线程 + 有界队列 + 丢最旧帧 + shared_ptr 流转；
- 上报：事件 JSON over TCP 到 `host/receiver.py`。
