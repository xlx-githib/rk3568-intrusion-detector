# 量化与 YOLOv5 后处理（study/03）

> 配套代码：`rknn_yolov5_demo/src/yolo_annotated.cc`（官方后处理逐行注释版）
> 说明：本文用「大白话 → 术语 → 函数/代码 → 通讲」的格式讲清 int8 量化、反量化与三个 process，并在末尾给出"移植到本工程"的对照。笔者的个人理解以"笔者认为"标注。

---

## 0. 为什么先讲帧率（帮你建立"瓶颈"直觉）

一帧总耗时 ≈ 采集 + 缩放 + **NPU 推理** + 后处理 + 显示。
- 纯摄像头预览（如 OV2640 直出）没有 AI，瓶颈只在采集/显示，所以能很高帧率；
- 一旦接入检测，RK3568 NPU 跑一个 640 检测模型约 40~70ms/帧（约 15~25fps 上限），**NPU 推理成为主瓶颈**。
- 提升方向（本项目架构动机）：C++ + 四线程流水线（采集与推理并行），而不是单线程逐帧串行。

## 1. 量化 / 反量化

### ① 大白话
NPU 为了快，把模型里大量"小数"压成 -128~127 的**整数(int8)**（体积小 4 倍、算得快）。
压完数值失真了，NPU 配一把"尺子"帮你还原：`真实值 = (int8值 − zp) × scale`。
- **反量化**：把 int8 还原成小数——因为"判断框可不可信、坐标多少"必须在小数上做。
- **为什么代码里又出现 float→int8**：把阈值(0.25)也压成 int8，格子直接用整数比大小，只有超阈值的才反量化，省掉大量无用计算。

### ② 术语
- 量化(Quantization)：float 权重/激活压成 int8，本项目用 rknn-toolkit 在 PC 上"训练后量化"完成，产物 `.rknn`。
- 仿射量化：$f=(q-zp)\cdot scale$；`scale` 缩放系数、`zp` 零点偏移。
- q8 后处理：拿 int8 原始输出，CPU 侧反量化后解码；fp 后处理：让 runtime(`want_float=1`)先转 float（省心但慢）。
- 阈值预量化：把 conf 阈值量化到 int8 域提前剔除。

### ③ 函数与代码
| 函数 | 作用 | 关键行 |
|---|---|---|
| `deqnt_affine_to_f32(qnt,zp,scale)` | 反量化 int8→float | `return ((float)qnt - zp) * scale;` |
| `qnt_f32_to_affine(f32,zp,scale)` | 量化 float→int8（压阈值） | `dst = f32/scale + zp` |
| `process_i8` 开头 | 阈值 0.25 → thres_i8 | `qnt_f32_to_affine(...)` |
| `process_i8` 内 | 超阈值才反量化解码 | `deqnt_affine_to_f32(...)` |

### ④ 通讲
模型输出 3 路 int8（stride 8/16/32）。`post_process`(老板) 把三路分给 `process_i8`/`process_fp`(员工) 解码出框 → 合并 → 按分排序 → NMS 去重 → letterbox 逆映射回原图 → 打包成 `detect_result_group_t`。
`process_i8` 与 `process_fp` 逻辑相同，区别只在输入是否要先反量化。

## 2. YOLOv5 解码（通俗版公式）

```
中心点x = (tx·2 − 0.5 + 列号j) × stride
宽      = (tw·2)² × anchor宽
左上角x = 中心x − 宽/2        （y/h 同理）
```
一句话：**中心 = (网络偏移 + 网格坐标) × stride；尺寸 = 网络值平方 × anchor**。
3 路输出 = 三个 stride(8/16/32) 网格，分别负责小/中/大目标。

## 3. 移植到本工程：官方代码 vs 你未来要写的代码

**官方**（通用 80 类，供画框）：
```cpp
detect_result_group_t { int count; detect_result_t results[200]; }
detect_result_t       { char name[16]; int class_index; BOX_RECT box; float prop; }
```

**本工程将来要写**（只留 person/car，喂给 ROI 状态机）：
```cpp
struct DetObject {          // src/common/frame.hpp 已有雏形
    int   cls_id;           // 0=person, 2=car (COCO)
    float conf;
    float x1, y1, x2, y2;
};

// 后处理→白名单（Infer 线程内）核心业务逻辑：
void postproc_whitelist(const std::vector<RawBox>& raw,
                        float conf_thres,
                        std::vector<DetObject>& out) {
    out.clear();
    for (const auto& b : raw) {
        if (b.cls != 0 && b.cls != 2) continue;   // ① 白名单 person/car
        if (b.conf < conf_thres) continue;        // ② conf 过滤(0.25)
        out.push_back({b.cls, b.conf, b.x1, b.y1, b.x2, b.y2});  // ③ 交给 business
    }
}
```

**移植地图**：
| 官方 yolo.cc | 本工程 | 处理 |
|---|---|---|
| `process_i8/process_fp`、NMS、letterbox | 后处理模块 | 纯数学，可照搬 |
| `detect_result_group_t`(80 类) | `DetObject` + 白名单 | 重写（业务差异点） |
| main.cc 摄像头/画框 | V4L2 + 输出模块 | 另写(M2) |
| 单线程 while | 四线程流水线 | 重写(architecture.md) |

> 笔者认为最有价值的一点：官方后处理是"能直接搬进你 C++ 工程"的数学代码；真正属于你写的是**数据结构 + 白名单 + 喂给 ROI 状态机**。
